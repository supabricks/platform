recorded in the [report](../../sync-performance-sp04.md). All 84 measurements are

- Root summaries and analysis scripts: recomputable derived attribution. `decision.json` records the keep decision and limits.

Outputs correspond to `component-summary.json`, `main-planning.json`, the two
control planning summaries, `paired-summary.json`, `main-profile.json`,
`main-resource.json`, and `wal-summary.json`. Component summary also appears
unchanged inside `component/summary.json`. Each experiment's compressed
`analysis-source.json.gz` contains its frozen comparison/harness source; extract
that into a temporary `e2e/native/performance/` directory (preserving its path depth)
to reproduce the original generic comparison with the harness dependencies installed.
Original generic `apply_directory_ms` counts only the old boundary span. Use
`planning_analysis.py` for the nonoverlapping sum of boundary, planning inventory
and planning check time. Never add nested parent/child counts or treat disabled
profiling as zero cost. Completed worker lifetimes can cross the load window;
sampled process CPU misses short-lived workers and exited tails, so it cannot
replace complete cgroup CPU. Three repeats do not imply statistical certainty.

Checksums bind all files except the root manifest itself and interpreter caches.
Child manifests remain immutable and bind each original archive. Source fixtures,
credentials, SQL traces and scratch process logs are excluded. Failure receipts
remain in `ci/`; no failed benchmark attempt was dropped or relabeled.
