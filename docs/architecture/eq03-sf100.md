## Capacity admission and first blocker

After user cleanup, `/data2` had 764 GiB available on 2026-10-08. That admits
generation. It is **not yet proof that the entire retained product workload fits**:
PostgreSQL data/indexes, pageserver/object history, safekeeper WAL, capture spool,
live and retained Delta roots, independent Spark input tables, outputs and spill
need a combined budget. The SF1 load retained about 21.3 GiB in its cell, but
blindly multiplying that by scale would mix fixed costs and historical growth.

[#213](https://github.com/supabricks/platform/issues/213) records the first
source-audit blocker: the incremental worker limits each generation to 1 GiB
and all retained roots to 4 GiB. Planning, rollover scheduling and Rust descriptor
validation independently enforce related bounds. A larger snapshot/export limit
does not enlarge incremental capacity. Compaction cannot solve an oversized live
set. The full SF100 load must not start with those defaults.

The [explicit storage-profile fix](eq03-storage-capacity.md) now passes the
installed Linux >1-GiB capacity/replay slice and native CLI-to-Sail profile
checks. Release CI remains pending. The loader now accepts explicit
`--workload sf100`, binding the actual generation receipt, scale, row inventory
and large storage profile. Reference and exact-verification admission remain
separate follow-up phases; no SF1 query result is accepted for SF100.

### First bounded load attempt

`e2e/tpcds/workload-sf100.json` defines a 96-hour outer load/drain deadline,
512-GiB sampled cell ceiling and 64-GiB remaining-free stop bound. Admission
requires 656 GiB free on the output filesystem: 512 GiB for the cell, 64 GiB
for exact-verification hashes, 8 GiB for evidence, 8 GiB for query spill and
64 GiB remaining free. This is permission for a bounded stress attempt, not
proof that all retained data fits. Storage is sampled every ten seconds and can
overshoot; exhaustion or sync failure stops the attempt with its state intact.
Spark reference tables will use separate admission on `/data`, outside the timed
product load. No reference generation runs concurrently with the load.

The load keeps the SF1 8-core/16-GiB container, no container swap, network disabled,
1,024 rows / 4 MiB maximum per COPY, and 65,536 unpublished-row backpressure.
The worker's 768-MiB / 300-second bounds and the 120-second SQL timeout stay
unchanged. The 96-hour allowance covers the full dataset; it does not extend an
individual worker deadline. The first non-ASCII customer-country control is
read from the selected dataset instead of relying on a scale-specific key.
